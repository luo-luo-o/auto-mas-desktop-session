## 进度与边界

- 集成分支把预览子进程、环境检查与修复移进桌面分身插件。主程序仍负责现有调度，并保留部分桌面分身专用 API、会话状态和进程操作。已有独立插件不满足任意干净 dev 上的安装与启用条件。
- 早期的 L1→L2 交接原型曾在 Win11 跑通隔离调度测试。随后被 L2→L3 的窄接口替换。完整工作树补丁保存的是最新版本。
- 最新原型在 L2 游戏设备选择前引入通用执行目标。普通任务仍沿用原有调度。测试执行目标连接真实 Windows 子会话启动器。桌面分身插件尚未通过这个接口跑完整的生产 L3–L4 链路。
- 如果将来只维护内置方案，现有主程序代码可继续演进。归档中的跨进程整任务接续、SDK 发布约束和适配器版本都要以那时的集成设计为准。

如需复跑原生测试，从交互式 Windows 账户运行探针脚本，准备同版本 MAS 源码、虚拟环境和测试依赖，并按实际目录调整探针内的旧宿主路径。将测试文件放入宿主的 tests/core，Python 探针、用户输入探针和 PowerShell 启动器放在该工作目录。Windows 登录凭据由测试机本地保存，测试时只复用当地已授权的加密配置，完成后删除临时副本。归档不包含密码、凭据文件、用户配置、游戏资源、私有启动脚本或原始运行日志。

## 恢复方式

推荐先在干净的临时工作树检出主程序基线 fecc70adb，在主程序仓库根目录执行：

~~~powershell
git apply --check <归档目录>/patches/auto-mas-complete-worktree.patch
git apply <归档目录>/patches/auto-mas-complete-worktree.patch
~~~

如果只需要还原较早的集成提交历史，从 c68ef1a51 起按文件名顺序执行 git am，使用 integration-history 目录的 8 个补丁。**完整工作树补丁和集成历史补丁是两种恢复入口，请择一使用。** Windows 进程适配补丁在它自己的仓库应用，基线为 f38f80a。旧文档补丁从其提交的父提交恢复，附带的代码片段可能与最新工作树不同。
